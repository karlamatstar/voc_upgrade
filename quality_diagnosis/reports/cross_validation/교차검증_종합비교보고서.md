#### 실험군 A 케이스별 채점·실패 근거

<details><summary>TC-01 — 85.0 / 조건부 배포 가능, 개선 후 재검증</summary>

Interpreter는 질문의 핵심 필터를 잘 추출했고 Retriever는 관련 VOC 2건을 정확히 검색했다. Summarizer는 두 사례를 일반화하여 과도하게 종합한 부분이 있어 Critic이 이를 정확히 지적했으나, 최종 개선안(Improver)에는 이 지적이 반영되어 사례별로 분리된 구체적 조치가 잘 제시됐다. Evaluator의 점수 근거는 타당하나 근소한 차이 설명이 다소 단순하다. 다만 Critic이 지적한 need_refine=true임에도 Summarizer 결과가 실제로 재생성되지 않은 채 Improver로 넘어가 Agent 연계 품질이 다소 감점된다. 로그와 타이밍 정보는 투명하게 제공되었고 전체 응답시간(25.65초)은 시연 허용 범위 내이다.

</details>

<details><summary>TC-02 — 77.0 / 주요 개선 필요</summary>

Interpreter는 팩스/이메일/접수확인 등 핵심 필터를 잘 추출했다. Retriever는 관련 2건을 정확히 찾았으나 표본이 적어 '공통 불편'을 일반화하기엔 근거가 약하다. Summarizer는 핵심을 간결히 담았으나 팩스/이메일 각각의 차이점(비교 요소)이 빠졌다. Evaluator는 점수 근거가 짧고 S0,S1과의 비교 설명이 부족하다. Critic은 표본 부족, 비교 분석 미흡 등 실제 한계를 전혀 지적하지 않아 위험 탐지력이 낮다. Improver는 구체적 실행안을 제시했으나 required_output 항목인 '우선순위'가 명시적으로 정리되지 않았다. 로그는 타이밍과 단계별 추적이 잘 제공되었고, 응답시간은 수업 시연에 허용 가능한 수준이다.

</details>

<details><summary>TC-03 — 79.0 / 주요 개선 필요</summary>

Interpreter는 질문 의도를 필터로 잘 반영했고 Retriever도 관련 VOC 3건을 적절히 검색했다. Summarizer는 핵심을 왜곡 없이 요약했으나 required_output 항목(공통 문제, 고객 영향, 원인 추정, 개선안, 우선순위) 구조를 명시적으로 갖추지 못했다. Evaluator 평가는 근거가 다소 서술적이나 일관성은 있다. Critic은 need_refine=false로 처리해 요구된 출력 항목 누락, 우선순위 부재 등 실제 한계를 전혀 지적하지 못해 위험 탐지력이 낮다. Improver는 구체적 실행 방안을 제시했으나 우선순위 명시가 없어 required_output을 완전히 충족하지 못했다. 로그와 타이밍 정보는 투명하게 제공되었고 응답시간도 수업 시연에 허용 가능한 수준이다.

</details>

<details><summary>TC-04 — 84.0 / 조건부 배포 가능, 개선 후 재검증</summary>

Interpreter는 질문 의도를 적절히 필터로 변환했고 Retriever는 관련 VOC를 잘 검색했다. Summarizer는 왜곡 없이 핵심을 요약했으나 '고객 영향', '고객 안내' 항목이 명시적으로 구분되지 않아 required_output 충족이 다소 부족하다. Evaluator는 근거를 제시했으나 다소 피상적이며, Critic은 need_refine=false로 판단해 실질적 위험(개인정보, 사실 왜곡 등)을 깊이 점검하지 않아 위험 탐지력이 낮다. Improver는 구체적 조직·기한·실행방안을 제시해 실행 가능성이 높다. 로그와 타이밍 정보는 투명하게 제공되었고 응답시간도 수업 시연에 적합하다.

</details>

<details><summary>TC-05 — 79.0 / 주요 개선 필요</summary>

Interpreter는 질문 의도를 적절한 필터로 잘 분해했다. Retriever는 관련 VOC 2건을 검색해 핵심 사례를 확보했으나 수가 적어 다양성 확인이 어렵다. Summarizer는 두 사례를 하나의 사건처럼 뭉뚱그려 서술해 Critic이 지적한 대로 구분성이 부족하다. Evaluator는 근거를 제시했으나 점수 편차가 크지 않아 변별력이 약하다. Critic은 구체적 왜곡·일반화 문제를 정확히 짚어 위험 탐지력이 양호하다. Improver는 구체적 기한과 담당 부서, 실행 방법을 제시해 실행 가능성이 높으나, Critic의 수정 요청이 실제로 Summarizer 결과에 반영되지 않아(Improver:policy_received만 로그) Agent 간 연계가 완전하지 않다. 로그는 각 단계 타이밍과 이슈를 투명하게 기록했고, 전체 응답시간 16.82초는 시연용으로 허용 가능한 수준이다.

## 6. 실행 규칙과 그래프 활용

- 각 실험군은 지정된 생성·평가 제공자를 고정한다.
- API 호출은 한 번만 수행하며 재시도하거나 다른 제공자로 대체하지 않는다.
- 생성 또는 평가 API가 실패한 케이스는 N/A로 기록하고 다음 케이스를 계속한다.
- `교차검증_그래프데이터.csv`는 실험군×테스트 케이스 형태의 그래프 원본이다.
- 점수 추이, 실험군 평균, 항목별 평균, 수행시간, N/A 비율 그래프에 바로 사용할 수 있다.
