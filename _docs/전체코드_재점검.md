# 2026-07-15 전체 코드 재점검

## 점검 범위

- 최근 수정된 Retriever, Summarizer, Evaluator, Critic, Improver
- LLM Judge 실행 및 보고서 저장 흐름
- 20개 통합 테스트 케이스 구성
- GUI의 pytest 및 LLM Judge 실행 방식
- 현재 생성된 Judge 보고서

`_docs/example_Don't touch`는 비교를 위한 읽기만 수행했으며 수정하지 않았다.

## 최근 코드 변경 파악

- Retriever: 필터 일치 개수로 검색 결과를 정렬하고 관련성이 낮은 결과를 줄인다.
- Summarizer: 원본 VOC에 없는 사실·통계·수치를 만들지 못하도록 프롬프트를 강화했다.
- Evaluator: 실제 후보 키(S0, S1, S2)를 사용하도록 하고, 잘못된 winner 키를 보정하며
  선정 근거를 `_reason`으로 남긴다.
- Critic: 요약과 원본 VOC를 함께 받아 사실 왜곡 여부를 검토한다. 원본 데이터는
  Improver 입력과 최종 요약에서 다시 제거한다.
- Improver: 우선순위를 최대 3개로 제한하고 1024토큰 안에서 문장이 끝나도록 지시한다.
- LLM Judge: 각 케이스가 끝날 때마다 CSV와 Markdown 보고서를 갱신하여 중단 시에도
  완료된 케이스를 보존한다.

## 테스트 케이스와 실행 구분

- 통합 테스트 케이스: 총 20개
- TC-01~TC-18: 실제 6개 서버와 API를 사용하는 LLM Judge 대상
- TC-19~TC-20: pytest 장애 대응 전용이며 LLM Judge 자동 실행에서는 제외

GUI의 `전체 테스트(pytest)`는 위 20개를 모두 Judge로 채점하는 기능이 아니다.
다만 서버 6개가 켜진 상태에서는 다음 테스트들이 실제 파이프라인을 호출한다.

- `test_pipeline_e2e.py`: 13회
- `test_mcp_tools.py`: 2회
- `test_fault_tolerance.py`의 빈 질문 검사: 1회

따라서 전체 pytest는 서버가 켜진 상태에서 최대 16회의 실파이프라인 호출과 API 사용이
발생할 수 있으며 실행 시간이 길어질 수 있다.

## 현재 Judge 보고서 상태

현재 `quality_diagnosis/reports`의 보고서는 TC-01과 TC-02, 총 2건만 기록되어 있다.

- TC-01: 85점
- TC-02: 72점
- 현재 기록된 2건 평균: 78.5점
- 주요 약점: Critic 위험 탐지력, 필수 출력 완전성, 110~142초의 응답시간

이는 전체 18개 실채점 완료 결과가 아니라 중간 저장 결과다.

## 확인된 주의점

### 1. 중간 보고서가 최종 보고서처럼 표시됨

LLM Judge는 케이스마다 보고서를 저장한다. 현재처럼 2건 처리 후 중단되면 보고서에
`전체 케이스: 2`와 `최종 배포 판정`이 표시된다. 실제 목표인 18건 중 2건만 끝났다는
표시가 없어 완성된 최종 보고서로 오해할 수 있다.

### 2. 전체 pytest가 서버 상태에 따라 API를 사용함

GUI 버튼 이름은 `전체 테스트(pytest)`이지만 서버가 켜져 있으면 E2E와 MCP 테스트가
실제 OpenAI·Anthropic 호출을 수행한다. 단순 로컬 검사로 오해하면 예상보다 오래
걸리거나 API 사용량이 발생할 수 있다.

### 3. 최근 핵심 개선 로직의 직접 단위 테스트가 부족함

현재 단위 테스트는 파일 존재, 문법, 필수 클래스·함수와 Judge 파서 중심이다. 다음 변경은
직접 검증하는 단위 테스트가 아직 없다.

- Retriever 관련성 정렬과 임계값
- Evaluator winner 키 보정 및 `_reason`
- Critic 원본 데이터 구분자 제거
- 중단된 Judge 보고서의 진행 상태 표시

### 4. README의 API 역할 한 줄이 실제 코드와 다름

README는 Retriever도 OpenAI API를 사용한다고 설명하지만 Retriever는 CSV 검색만 수행한다.
실제 OpenAI 사용 에이전트는 Interpreter, Summarizer, Evaluator, Critic이다.

## 종합 판단

최근 변경은 검색 정확성, 요약 사실성, 평가 근거, 원문 기반 Critic 검토를 강화하는 방향으로
서로 잘 연결되어 있다. 문법과 서버 비의존 검사는 정상이다. 다만 현재 보고서는 2건짜리
중간 결과이며, 전체 18건 완료로 해석하면 안 된다. 다음 개선 우선순위는 중간/완료 보고서
구분, 전체 pytest의 API 사용 안내, 최근 개선 로직의 직접 단위 테스트 추가 순서가 적절하다.
