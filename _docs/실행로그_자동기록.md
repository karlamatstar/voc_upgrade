# pytest 및 LLM Judge 실행 로그 자동 기록

## 변경 목적

향후 DOCX 보고서 2종을 자동 생성할 때 필요한 실행 근거를 남기기 위해 pytest와
LLM Judge 실행 결과를 구조화된 로그로 자동 저장하도록 개선했다.

## 로그 위치

```text
quality_diagnosis/reports/logs/
├── pytest/
│   ├── pytest_실행ID.json
│   └── pytest_실행ID.log
└── llm_judge/
    └── llm_judge_실행ID.json
```

## pytest 로그 내용

- 실행 ID와 실행 종류
- 시작·종료 시각 및 실행시간
- Python·운영체제 정보
- 수집·통과·실패·오류·건너뜀 건수
- 테스트별 결과, 단계, 소요시간
- 실패 및 건너뜀 상세 내용

`quality_diagnosis` 아래에서 pytest 또는 단위 테스트를 실행하면 자동 생성된다.

## LLM Judge 로그 내용

- 실행 ID와 실행 상태(`running`, `completed`, `interrupted`, `failed`)
- 시작·종료 시각
- 설정된 provider와 모델 호출 순서
- 전체 정의 케이스, Judge 대상, 처리·채점·N/A·미채점 건수
- 케이스별 점수, 판정, API 시도, 즉시 보류 여부와 근거
- CSV 및 Markdown 결과 파일 경로

LLM Judge는 케이스가 끝날 때마다 JSON 로그를 갱신한다. 실행이 중간에 중단되더라도
마지막으로 완료된 케이스까지의 진행 상태가 남는다.
