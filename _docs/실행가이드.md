# VOC Improve 및 QA 프로젝트 — 실행 가이드 (d:\voc)

`_docs`의 스펙과 example을 기반으로 구성한 프로젝트입니다. 모든 경로는 `d:\voc` 기준입니다.

## 폴더 구조

```
d:\voc\
├── main.py                  # MCP 서버 진입점 (VS Code 채팅과 연결)
├── grpc_server.py           # 전체 Agent 호출 담당 (오케스트레이터)
├── voc.proto / voc_pb2.py / voc_pb2_grpc.py
├── voc.csv                  # VOC 데이터 (보험 고객 불만 50건)
├── agents\                  # 6개 에이전트 (interpreter ~ improver)
├── llm_wrappers\            # OpenAI / Anthropic 래퍼
├── utils\                   # 설정, MCP 도구 정의
├── quality_diagnosis\       # QA1 (pytest) + QA2 (LLM Judge)
│   └── reports\             # 테스트·채점 결과 보고서
├── .vscode\mcp.json         # VS Code MCP 등록 설정
└── _docs\                   # 프로젝트 관련 명세서, 가이드, 테스트 리포트 등 모든 문서 모음
```

## 1. 최초 1회: 환경 준비

```powershell
cd d:\voc
python -m venv .venv
.\.venv\Scripts\Activate.ps1

pip install openai anthropic grpcio grpcio-tools protobuf mcp pytest

# gRPC 코드 생성 (voc_pb2.py, voc_pb2_grpc.py)
python -m grpc_tools.protoc -I. --python_out=. --grpc_python_out=. voc.proto
```

## 2. API 키 등록 (최초 1회, 등록 후 새 터미널 필요)

```powershell
setx OPENAI_API_KEY "sk-proj..."
setx ANTHROPIC_API_KEY "sk-ant-..."
```

## 3. 에이전트 6개 실행 — PowerShell 창 6개

각 창에서 `cd d:\voc` → `.\.venv\Scripts\Activate.ps1` 후 하나씩:

```powershell
python -m agents.interpreter   # 6001
python -m agents.retriever     # 6002
python -m agents.summarizer    # 6003
python -m agents.evaluator     # 6004
python -m agents.critic        # 6005
python -m agents.improver      # 6006
```

가동 확인:

```powershell
netstat -ano | findstr 600
```

## 4. VS Code에서 MCP로 사용하기

`.vscode\mcp.json`이 이미 준비되어 있습니다. VS Code에서 d:\voc 폴더를 열고
채팅(Copilot Chat)에서 MCP 서버 `vocMcp`를 시작한 뒤 이렇게 질문합니다:

> VOC 관련 도구를 사용하여 다음 고객 불만을 분석해 주세요.
> "결제는 완료되었는데 주문 내역에 보이지 않습니다."
> 1. 핵심 의도 해석 2. 원인 분류 3. 답변 초안 4. 개선안 제안

- `main.py`는 직접 실행하지 않습니다 (VS Code가 MCP로 자동 실행).
- `grpc_server.py`는 gRPC 연결 점검용으로만 직접 실행합니다.

## 5. QA1: 내부 품질 진단 (pytest)

```powershell
# 에이전트별 단위 테스트 (서버 불필요)
pytest quality_diagnosis/test_agent_unit.py -v

# 6개 에이전트 전체 연결 테스트 (서버 6개 필요, 꺼져 있으면 SKIP)
pytest quality_diagnosis/test_pipeline_e2e.py -v

# 장애·예외 처리 테스트
pytest quality_diagnosis/test_fault_tolerance.py -v

# MCP 도구 테스트
pytest quality_diagnosis/test_mcp_tools.py -v

# 전체 한 번에
pytest quality_diagnosis -v

# 결과를 파일로 남기기
pytest quality_diagnosis -v | Tee-Object -FilePath quality_diagnosis\reports\pytest_result.txt
```

테스트 기준: `quality_diagnosis\test_cases.json` (질문·기대 결과·Judge 실행 여부를 한 항목에서 함께 관리)
배점표: `quality_diagnosis\evaluation_rubric.csv` / 결함 기록: `_docs\defect_report.md`

## 6. QA2: 독립 LLM Judge

```powershell
.\.venv\Scripts\Activate.ps1
pytest quality_diagnosis/test_llm_judge.py -v      # 단위 테스트 (API 키 불필요)
python quality_diagnosis/llm_judge.py               # 실제 채점 (API 키 필요)

Get-Content quality_diagnosis\reports\llm_judge_result.csv        # 케이스별 원본 데이터
Get-Content quality_diagnosis\reports\quality_score_report.md     # 점수표 + 케이스별 근거 + 최종 배포 판정
```

자세한 내용: `_docs\README_LLM_JUDGE.md`
