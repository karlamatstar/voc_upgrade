# Retriever 검색 과다 매칭 개선 기록

- 작업일: 2026-07-15
- 대상: `agents/retriever.py`
- 목적: 관련 VOC가 있는데 0건이 되는 문제와 범용 단어 때문에 과다 검색되는 문제를 함께 완화

## 변경 전 문제

기존 Retriever는 긴 필터에서 단어 하나만 겹쳐도 필터 일치로 계산했다. 또한 관련성 기준을 통과한 결과가 0건이면, 이미 탈락시켰던 낮은 관련성 결과를 다시 사용했다. 이 때문에 `VOC`, `고객`, `문제`, `개선`, `원인` 같은 범용 표현이 다른 주제의 VOC까지 검색하는 원인이 되었다.

## 개선된 검색 흐름

```text
필터 정규화
→ 조사 제거·중복 통합·범용어 제외
→ 1차 원문 핵심어 복수 일치 검색
→ 1차가 0건일 때만 제한적 동의어 검색
→ 필요한 경우 CSV에서 드물게 나오는 구체어 검색
→ 여전히 기준 미달이면 0건 반환
```

## 주요 변경 내용

1. `VOC`, `고객`, `문제`, `원인`, `개선`, `분석`, `보완` 등을 검색 점수에서 제외했다.
2. `오류의/오류`, `지연과/지연`처럼 조사가 붙은 표현을 원형으로 통합했다.
3. TC-07과 같은 띄어쓰기·오타 문장에서 `보험금`, `청구`, `약관`, `거절` 등의 도메인 단어를 복원한다.
4. `고객센터/콜센터`, `지연/대기`, `불친절/태도` 등은 1차 검색이 0건일 때만 확장한다.
5. 서로 같은 동의어 그룹은 하나의 개념으로 세어 점수 부풀림을 방지했다.
6. CSV 전체의 15% 이하에 나오는 드문 구체어는 한 단어 일치를 제한적으로 허용했다.
7. `게임+아이템+환불`처럼 CSV에 없는 핵심 주제어가 2개 이상이면 희소 단어 완화를 중단한다.
8. 필터 검색 결과는 관련성 상위 10건으로 제한했다.
9. CSV 헤더는 검색 대상에서 제외했다.

## 검증 결과

- Retriever 전용 및 기존 에이전트 단위 테스트: `35 passed`
- 소스 문법 검사: 통과
- API 호출: 없음
- 전체 LLM Judge: 미실행

## 해석 시 주의사항

위 표본 결과는 Retriever에 테스트 케이스의 `expected_keywords`를 직접 적용한 결과이다. 실제 LLM Judge에서는 Interpreter가 생성한 필터가 합쳐지므로 건수가 달라질 수 있다. 최종 품질은 다음 LLM Judge 실행에서 `intent_json`, `Retriever:count`, 검색 고객 ID를 함께 보고 판단해야 한다.
