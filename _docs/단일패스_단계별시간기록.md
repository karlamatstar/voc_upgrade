## 변경한 실행 흐름

기존에는 Critic이 요약을 검토한 뒤 Summarizer를 다시 호출할 수 있었고, Improver도
정책을 만든 뒤 Critic을 다시 호출하여 정책을 재작성할 수 있었다. 이 구조는 최초
결함을 가리고 API 호출 횟수와 수행시간을 늘릴 수 있었다.

주 실행 경로를 다음의 단일 패스로 변경했다.

```text
Interpreter → Retriever → Summarizer → Evaluator → Critic → Improver → 독립 LLM Judge
```

- Critic은 문제와 수정 의견을 기록하지만 Summarizer를 재호출하지 않는다.
- Improver는 Critic의 기록을 참고해 정책 개선안을 한 번만 생성한다.
- Improver가 Critic을 역호출하지 않는다.
- Judge는 최초 단일 패스 결과를 그대로 채점한다.
